# Sales Analytics Dashboard

Link: https://sales-analytics-dashboard-4smrhhviwtwwcembahfqbm.streamlit.app/

A project that takes raw sales records from a fictional online store and
turns them into three things a business would actually want to know:

1. **How are we doing?** — revenue, orders, average order size, and which
   regions/products are winning, as an interactive dashboard.
2. **Which customers matter most?** — every customer sorted into groups
   like "Champions" or "At Risk" based on how recently, how often, and how
   much they buy (this technique is called **RFM analysis**).
3. **What will we sell next month?** — a 6-month revenue forecast built
   from the seasonal pattern in past sales (e.g. everyone buys more in
   December), using a method called **Holt-Winters**.

The data is 100% synthetic (generated by a script, not real customers), so
it's safe to explore, break, and rebuild from scratch.

## How the pieces fit together

```
raw CSV  --->  SQL database  --->  analysis + charts
(fake sales     (customers,         (dashboard, forecast,
 data)           orders, etc.)       customer groups)
```

1. `src/generate_sales_data.py` invents ~12,000 realistic order line items
   (customers, products, dates, discounts) and saves them as a CSV.
2. `src/load_to_sql.py` reorganizes that flat CSV into a proper relational
   database (separate tables for customers, products, orders — the kind of
   structure a real company's database would use).
3. `src/forecasting.py` and `src/segmentation.py` run the analysis: one
   predicts future revenue, the other groups customers.
4. `dashboard/app.py` displays everything as an interactive web page.

## Quickstart

You'll need Python installed. Then, from the project folder:

```bash
pip install -r requirements.txt

# Run these once, in order, to build the data and analysis:
python src/generate_sales_data.py    # creates data/raw/sales_data.csv
python src/load_to_sql.py            # creates data/processed/sales.db
python src/forecasting.py            # creates the revenue forecast
python src/segmentation.py           # creates the customer groups

# Then launch the dashboard:
streamlit run dashboard/app.py
```

This opens the dashboard at http://localhost:8501 in your browser. Use the
filters on the left to narrow down by date, region, or category — every
chart, the forecast, and the customer segments update live.

## What is RFM analysis, really?

Score every customer on three numbers:
- **R**ecency — days since their last order (lower is better)
- **F**requency — how many orders they've placed (higher is better)
- **M**onetary — how much they've spent total (higher is better)

Customers with similar scores get grouped together automatically (using a
clustering algorithm called KMeans — think of it like sorting a scatter
plot of dots into 4 natural clumps). The result: instead of looking at 800+
individual customers, you get 4 meaningful groups to make decisions about
(e.g. "send a win-back discount to the At Risk group").

## What is the Holt-Winters forecast, really?

It looks at monthly revenue history and separates it into two patterns: an
overall trend (growing/shrinking) and a repeating seasonal wave (e.g. a
holiday spike every December). It then extends both patterns 6 months into
the future. It's the same idea as noticing "ice cream sales always spike in
July" and using that to guess next July's sales.

## SQL analysis

`sql/analysis_queries.sql` has 7 standalone queries you can run against
`data/processed/sales.db` with any SQLite tool — headline KPIs, revenue by
region/category, month-over-month growth, top products, the RFM numbers,
and the effect of discounts.

## Power BI

Power BI Desktop only runs on Windows, so this repo doesn't include a
`.pbix` file — but `powerbi/README.md` documents exactly how to rebuild the
same report there (data model, relationships, and the formulas/measures
needed), using `data/processed/sales.db` and the `powerbi_*.csv` exports.
